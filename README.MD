# certscan: инструкция для тех, кто чуть-чуть знаком с Python

## Что это вообще такое

Программа читает сертификаты о повышении квалификации (PDF, фото, скан) и сама заполняет таблицу: ФИО, название курса, организация, часы, даты, направление. Для чтения документа она отправляет его нейросети (Gemini от Google или Groq), а вы потом проверяете результат глазами и нажимаете «Подтвердить».

Состоит из двух частей:

- **Бэкенд** (`app.py`, `extract.py`, `db.py`): невидимая «кухня» на Python. Принимает файлы, общается с нейросетью, хранит записи в базе.
- **Интерфейс** (`ui/index.html`): страница в браузере, где вы загружаете файлы и правите результат.

Бэкенд запускается одной командой и сам показывает интерфейс в браузере. Ничего устанавливать для интерфейса не нужно.

---

## Что понадобится

1. **Python версии 3.10 или новее.** Проверить: откройте терминал и введите `python --version` (на Mac/Linux может быть `python3 --version`). Если Python нет, скачайте с python.org. На Windows при установке поставьте галочку **Add Python to PATH**.
2. **Ключ нейросети**, хотя бы один. Он нужен только для настоящей обработки, для знакомства с интерфейсом можно обойтись без него (см. «Режим демо»).
   - Gemini: ключ создаётся в Google AI Studio (aistudio.google.com).
   - Groq: ключ создаётся в консоли Groq (console.groq.com).
3. Любой текстовый редактор (подойдёт Блокнот) и браузер.

> **Терминал** это окно, куда вводятся команды. Windows: нажмите Win, наберите `PowerShell`, откройте. Mac: программа «Терминал». Каждую команду ниже вводите и жмите Enter.

## Как должны лежать файлы

Распакуйте `certscan.zip` в любую папку (например, `C:\certscan` или `~/certscan`) и сделайте так:

```
certscan/
├── app.py            <- ЗАМЕНИТЕ на новый
├── extract.py        <- ЗАМЕНИТЕ на новый
├── db.py
├── config.yaml
├── requirements.txt
├── .env.example
├── test_smoke.py
└── ui/
    └── index.html    <- новый файл, папку ui создайте сами
```

Новые `app.py` и `extract.py` отличаются от старых тем, что умеют принимать ключ и выбор модели прямо со страницы.

---

## Режим демо: посмотреть интерфейс за 10 секунд

Если хочется просто увидеть, как всё выглядит, без установки чего-либо:

1. Дважды щёлкните по `ui/index.html`. Он откроется в браузере.
2. Вверху будет жёлтая метка «демо-режим: бэкенд не найден». Это нормально.
3. Внутри три примера записей. Можно кликать по ним, править поля, нажимать «Подтвердить», перетащить любой файл (результат будет выдуманный, нейросеть не вызывается) и выгрузить CSV.

Деньги и ключи в этом режиме не используются.

## Настоящий запуск: по шагам

### Шаг 1. Откройте терминал в папке проекта

- **Windows:** откройте папку `certscan` в проводнике, щёлкните в адресную строку, наберите `powershell`, Enter.
- **Mac/Linux:** в терминале `cd путь/до/certscan`.

### Шаг 2. Создайте «виртуальное окружение»

Это отдельная коробочка для библиотек проекта, чтобы они не мешали остальному на компьютере. Делается один раз.

```
python -m venv .venv
```

(на Mac/Linux: `python3 -m venv .venv`)

### Шаг 3. Включите это окружение

Windows (PowerShell):
```
.venv\Scripts\Activate.ps1
```
Mac/Linux:
```
source .venv/bin/activate
```

Если всё получилось, в начале строки терминала появится `(.venv)`. Включать окружение нужно **каждый раз**, когда открываете новый терминал.

> Если на Windows PowerShell ругается на «выполнение сценариев отключено», введите один раз
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, подтвердите и повторите шаг 3.
> Или используйте обычную командную строку (`cmd`) и команду `.venv\Scripts\activate.bat`.

### Шаг 4. Установите библиотеки

```
pip install -r requirements.txt
```

Подождите пару минут, пока всё скачается. Делается один раз.

### Шаг 5. Положите ключ в файл `.env`

1. Скопируйте файл `.env.example` и назовите копию `.env` (с точкой в начале, без `.example`).
   Windows: `copy .env.example .env`, Mac/Linux: `cp .env.example .env`.
2. Откройте `.env` в редакторе и впишите ключ после знака `=`, без пробелов и кавычек:
   ```
   GEMINI_API_KEY=AIzaSy...ваш_ключ
   GROQ_API_KEY=
   ```
   Второй можно оставить пустым.

Это необязательно: ключ можно ввести позже прямо на странице (шаг 7). Файл `.env` никому не показывайте и не отправляйте.

### Шаг 6. Запустите программу

```
uvicorn app:app --reload
```

В терминале появятся строки вроде `Uvicorn running on http://127.0.0.1:8000`. Терминал теперь «занят», это значит, что программа работает. **Не закрывайте его.** Остановить программу: Ctrl+C.

### Шаг 7. Откройте интерфейс

В браузере откройте **http://localhost:8000/**

- Вверху справа должна быть **зелёная** метка. Если там написано «нет ключа», красная точка: нажмите **«Настройки и ключи»**, выберите провайдера, вставьте ключ в нужное поле, нажмите **«Сохранить и проверить»**.
- Выбирайте в настройках того провайдера, чей ключ вставили. Выбор Gemini с ключом только от Groq работать не будет.
- Ключи из настроек хранятся в вашем браузере и уходят на ваш же компьютер, где запущен бэкенд. Кнопка «Стереть ключи» убирает их.

### Шаг 8. Загрузите сертификат

Перетащите файл в рамку слева (или кликните по ней). Через 5–30 секунд запись появится в списке. Выберите её, слева от формы увидите оригинал, справа распознанные поля. Поправьте, что нужно, и нажмите **«Подтвердить и сохранить»**.

## Как читать цветные точки у полей

| Точка | Что значит |
|---|---|
| Зелёная | Нейросеть привела цитату из документа, и эта цитата действительно найдена в тексте PDF. Можно доверять, но глазами всё равно лучше проверить |
| Жёлтая | Цитата в тексте **не найдена**. Нейросеть могла ошибиться или выдумать. Проверьте это поле |
| Серая | Документ был картинкой или сканом, автопроверки нет. Проверяйте сами |
| Синяя | Поле вы исправили вручную |

Наведите мышку на точку, увидите цитату.

Статусы записи: **Авто** (всё сошлось), **Проверить** (чего-то не хватает или есть сомнения), **Подтверждено** (вы проверили).

## Как проверить, что всё работает

### Проверка 1: бэкенд жив

Откройте http://localhost:8000/health. Должно быть что-то вроде:
```
{"ok":true,"provider":"gemini","model":"...","key_present":true,"llm_calls_used":0,"llm_calls_max":50}
```
`key_present: true` значит, что ключ из `.env` найден. Если `false`, а вы вводите ключ на странице, это нормально.

### Проверка 2: страница автодокументации

http://localhost:8000/docs показывает все команды бэкенда, и их можно пробовать прямо там кнопкой «Try it out».

### Проверка 3: настоящий сертификат

Лучше всего проверить два вида файлов:

1. **PDF с текстом** (например, сохранённый из Word). В карточке будет пометка «текстовый слой», а у полей зелёные точки.
2. **Фото или скан** (JPG, PNG). Пометка «изображение», точки серые.

Используйте обезличенные образцы, если есть возможность: ФИО уходят во внешний сервис.

### Проверка 4: кэш

Загрузите тот же файл второй раз. Появится сообщение «уже обработан раньше, LLM не вызывался». Это правильно: так экономятся деньги и лимиты.

### Проверка 5: ручная правка и CSV

Измените любое поле, нажмите «Подтвердить и сохранить». Точка у этого поля станет синей. Перезагрузите страницу: правка должна остаться. Кнопка «Экспорт CSV» скачивает таблицу, которая открывается в Excel.

### Автотесты (по желанию)

```
pytest -q
```

Они работают без интернета и без ключей: вместо нейросети подставляется заглушка. Но в тестах прописан путь к шрифту Linux (`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`). На Windows и Mac часть тестов может упасть из-за этого, а не из-за ошибки в программе. Если так, не пугайтесь: проверяйте руками по пунктам выше.

## Если что-то пошло не так

| Что видите | Что делать |
|---|---|
| `python` не находится | Переустановите Python с галочкой Add Python to PATH, откройте терминал заново. На Mac/Linux пробуйте `python3` |
| `uvicorn` не находится | Забыли включить окружение (шаг 3) или не сделали шаг 4 |
| «Address already in use» | Порт 8000 занят. Запустите на другом: `uvicorn app:app --port 8001` и откройте http://localhost:8001/ |
| Метка «демо-режим: бэкенд не найден» | Бэкенд не запущен, либо вы открыли `index.html` двойным кликом. Откройте именно http://localhost:8000/ |
| Красная метка «нет ключа» | Вставьте ключ в «Настройки и ключи» или в `.env` и перезапустите |
| Ошибка `HTTP 400/401/403` от провайдера | Ключ неверный, протух или без доступа к модели |
| Ошибка `429` или «Достигнут лимит LLM-вызовов» | Либо лимит у провайдера, либо внутренний лимит 50 вызовов за запуск (см. `max_llm_calls` в `config.yaml`). Перезапуск бэкенда обнуляет внутренний счётчик |
| `413` | Файл больше 10 МБ |
| `415` | Формат не поддерживается, нужны PDF, JPG или PNG |
| `422` | PDF пустой, битый или длиннее 3 страниц |
| Ошибка про невалидный JSON | Нейросеть ответила мусором, просто повторите. Если повторяется, попробуйте другую модель в настройках |
| Поля пустые или странные | Скан плохого качества. Лучше загрузить более чёткий файл |

### Как «забыть» все загруженные файлы и начать заново

Остановите программу (Ctrl+C), удалите папку `data` рядом с `app.py`, запустите заново. Там лежат база записей и копии загруженных файлов.

## Что можно настраивать без знания Python

Всё в файле `config.yaml`, открывается в Блокноте:

- `provider` и `model`: какая нейросеть по умолчанию.
- `directions`: список «направлений», из которых нейросеть выбирает одно. Если поменяете, поменяйте и список `D` в начале скрипта в `ui/index.html`, чтобы выпадающий список в форме совпадал.
- `limits`: максимальный размер файла, число страниц, лимит вызовов.
- `prompts`: тексты инструкций для нейросети. Здесь настраивается, как именно она читает сертификаты.

После правки `config.yaml` перезапустите программу (Ctrl+C, затем снова команда из шага 6; при флаге `--reload` перезапуск идёт сам только при изменении `.py`-файлов).

## Важно про приватность

Сертификаты содержат ФИО. Каждый обработанный файл целиком уходит стороннему сервису (Google или Groq). Для реальных данных сотрудников нужно согласование, для обучения и демонстрации используйте обезличенные образцы. Ключи не выкладывайте в публичные места и не отправляйте в чаты.
